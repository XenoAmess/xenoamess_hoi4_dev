# 中国共产党相关素材的发布排除规则

2026-11-18 用户要求：中国红军、新四军等中国共产党及其相关势力的图片可以生成、审图、进入 Git 素材库，但禁止进入最终 mod 安装包。这些素材的缺失、生成失败、冷却、待审或返修状态均不阻塞 mod 发布。用户随后明确范围仅限中国共产党及其相关势力，不整体排除苏联、蒙古、朝鲜等外国共产党势力。

这是一项永久发布规则。根目录和本产品的 `AGENTS.md` 同时保存要求；既有完整提示词、原始 PNG、历史失败和审图记录照常保留，不将被排除的图片伪记为制作完成，也不删除其历史记录。

## 分类依据与共享图片

机器规则在 [`release-exclusion-policy.json`](../data/release-exclusion-policy.json)，当前来源快照在 [`release-scope.json`](../data/release-scope.json)。后者由 `release_scope.py` 生成，禁止手改。分类依据是当前原版人物定义、来源引用、专用来源身份及明确核查的相关人物。不能只凭 `PRC` 文件夹名称判断：该目录也包含蒙古乔巴山、朝鲜金日成及其他中国人物；外国人物和明确核查的非共产党替代路线不会因为目录位置而被整体排除。

当前显式相关身份包括宋庆龄、陈铭枢、张国焘，以及原版中国区域势力中的共产党或相关角色。游戏定义中的马克思主义、列宁主义、斯大林主义及无政府共产主义路线用于识别相应游戏角色；这不等于声称每个人都是中国共产党党员。例如盛世才的游戏定义包含 `stalinism` 和 `SIK_communist_in_name_only`，其区域相关角色被纳入，而不是据此编造党籍。

宋庆龄的相关身份亦有[全国政协的生平资料](https://www.cppcc.gov.cn/2011/06/27/ARTI1309159173171135.shtml)支持。新疆相关历史背景参见[新疆维吾尔自治区档案馆资料](https://www.xjaa.gov.cn/content/21/507.html)。其他分类的直接证据是当前本机原版人物定义及库存引用，不公开上传完整游戏资产；本机观察及文件 SHA 保存在私有诊断记录中。政策清单列出具体身份，避免把历史人物关系、游戏意识形态和党籍混为一谈。

同一原始 SHA 如果被排除角色使用，其全部字节相同别名也不输出。为避免较旧 DLC 或其他 profile 回流，同一虚拟路径的旧来源及其别名按固定点闭包继续排除。若这连带影响其他国家共用的通用头像，该通用替换图也省略，游戏使用原版资源；这不将外国共产党势力整体改判为排除对象。库存同时保存每条排除理由和来源绑定，不能用另一张人物图填补被省略的位置。

## 构建与覆盖统计

默认构建、开发子集和发布副本重打包均执行过滤。`art_complete` 按允许发布的图片判断；`archive_art_complete` 保留整个素材库存的真实完成状态，缺口分别记录。`portraits.py coverage --public` 也分别报告归档素材和发布范围，不靠修改原图审查资格实现排除。

当前排除候选和保留例外已按本机人物定义及库存引用核查，结果绑定整个库存的稳定指纹。游戏更新改变来源、路径或人物引用后，必须重新检查变化的身份和引用，再更新政策指纹及快照。新出现且未分类的 `PRC` 目录来源阻止打包，不能自动猜测归属。已确认排除素材本身的制作缺口不阻塞；其他人物的缺口、非人物范围判断、格式和实机验收要求仍分别执行。

```text
python -X utf8 mod_nailong/tools/release_scope.py
python -X utf8 mod_nailong/tools/portraits.py coverage --public
```

只有实际核查库存变化后，才可使用 `release_scope.py --review-current-inventory` 记录新的核查指纹。此命令是维护工具，不能作为跳过归属核查的惯例。

## 发布前的额外审计

构建完成后自动生成 `release-exclusion-audit.json`。本地部署及重打包也强制审计。**在 Steam 创意工坊上传和 GitHub Release 上传 mod ZIP 之前，发布执行者必须对最终那一份构建再运行一次独立审计，并保存新的回执：**

```text
python -X utf8 mod_nailong/tools/release_exclusion_audit.py --build <最终构建目录> --receipt <新的审计回执.json>
```

审计重新读取当前政策、库存、manifest、实际 staging 文件和 ZIP 内容，检查来源与当前已审母版绑定、排除来源及路径、历史母版 SHA、额外文件、大小及 SHA、ZIP 与 staging 字节一致性，以及绑定到该 manifest 的逐图原尺寸 RGBA 验证证明。独立排除审计复核原尺寸像素证明和实际输出字节，不声称自己再次计算了全部高清母版像素。

失败时立即停止发布并保存失败回执；不得上传旧构建或绕过审计。文件、manifest、政策、来源库存或重打包结果发生变化后，旧回执不再证明当前安装包，必须重新审计。上传后仍需按原流程读回 GitHub 资产和 Steam 真实订阅字节，与刚审计的安装包核对。审计通过只证明本排除规则及所列文件检查通过，不等于全量美术或实机验收完成。

本次规则对之后的构建和发布生效。旧发布记录和旧视频保持其真实历史状态，不能把写入规则或本地子集验证冒充已经更新了公开安装包。
