# 旧拒绝请求的实际参数恢复

六个旧来源已超过八小时，但旧调用没有后来新增的调用前 UTF-8 参数校验回执。仅找到预期 prompt 文件还不足以安排严格的原请求重试，因此继续生产其他人物，同时核对原始执行记录。

本轮从原执行者仍保留的 `production_007_jobs`、`production_007_repair_jobs`、`production_009_jobs` JavaScript 缓存及对应历史执行代码，恢复了六次实际使用的 prompt、引用文件顺序与透明背景参数，并逐项核对现存输入文件 SHA。叶廖缅科匹配的是已拒绝的三输入局部编辑，不能拿先前已成功的两输入生成请求代替。

完整实际词、输入身份、原缓存定义和直接调用内置工具的代码来源见[恢复记录](../data/historical-payload-recovery-007-009.json)。这是事后核验，不追记为旧调用当时已经做过新的参数检查；原 prompt、失败事实、输入与冷却重试次数均未改写。恢复参数本身没有产生新图片，也没有消耗重试次数。

这些请求继续在单路生产队列中各重试一次，仍使用内置图片工具、完整原词与相同输入；旧编辑若使用游戏缩图，本次严格重试也保留原输入，不因新高清编辑规则替换它。只有实际返回并通过当前毛发和领口审图的结果才能计入合格进度，再次被拒绝的来源不自动增加重试。

第九轮另加入已到期的达尔朗原请求，实际参数另见[第十五批恢复记录](../data/historical-payload-recovery-darlan-015.json)。其历史原词传输包含四个 U+FFFD；本次严格重试保留这些实际字符、原输入顺序与透明背景参数。原始 JavaScript 参数快照的 SHA 与已入库的[传输更正](prompt-transport-correction-015.md)一致。没有把修正后的中文预期稿冒充原请求，也没有追认旧调用已完成事前参数校验。
