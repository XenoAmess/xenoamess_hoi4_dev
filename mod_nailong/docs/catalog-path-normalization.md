# 库存扫描的双斜杠路径更正

2026-10-17（Asia/Shanghai），在 `machine_id: bf-202609141645-5434332d4d` 的现有 HOI4 1.19.3.0 安装上，检查“sprite 已定义但目标纹理未找到”的记录时发现：原版部分字符串使用双反斜杠。旧扫描器只把每个反斜杠转成斜杠，产生 `gfx//leaders//...`，没有与真实虚拟路径 `gfx/leaders/...` 匹配。这是扫描器误报，不能归为原版缺失。

`catalog.py` 现在在 sprite 纹理与直接引用两处统一路径分隔符，同时保留实际文件路径、原始引用值、来源文件及 SHA。新增测试用真实临时图片、sprite 和角色定义验证两种引用均能绑定同一现存纹理，不只测试字符串替换。

先在 runtime 隔离输出重扫，再于 2026-10-16 20:07 UTC 前后更新 canonical 库存；游戏安装及版本没有因此改动。结果为：

| 项目 | 旧扫描 | 更正后 |
| --- | ---: | ---: |
| 纹理资源实例 | 5,274 | 5,369 |
| 不同原图 SHA | 5,129 | 5,224 |
| 高优先级原图 | 4,426 | 4,521 |
| 非高优先级原图 | 703 | 703 |
| 未解析引用次数 | 899 | 748 |
| 未解析不同值 | 852 | 709 |
| sprite 目标未解析的不同值 | 158 | 15 |

新增 95 张均为具名角色的小头像，已逐张审阅六页原图 contact sheet，确认含人物，全部进入高优先级；没有排除旧图片，也没有把找回的原图写成已生成。另有 46 张原已清点的独立人物补上了角色定义绑定，因此角色分类数量也随之调整。大小图的原始 SHA 不同仍分别生成。

旧 catalog 与引用报告由公开提交 `f38a0ca` 保全；旧日报、实验、实机及进度快照按当时口径保留。当前数量使用生成器重建的 catalog、production-priority 与 progress。机器、前后 SHA、95 个新增来源及审查页哈希见 [机器可读更正](../data/catalog-path-normalization-correction.json)。原图对照页仅留本机，不公开复制游戏图片。

剩余 748 次仍是当前扫描器未解析的引用，不能断言全部属于原版缺陷，也未据此证明引擎会显示何种 fallback。后续继续分析，正式完整覆盖门禁仍保留这些未决项。
