# 原请求审批的版本边界

本机实证：2026-10-20，机器 `bf-202609141645-5434332d4d`。Giovanni Messe 小卡片原请求已实际返回；帽徽返修也已实际返回，后续恢复照片内部背板的独立美术请求被拒绝。审批池仍绑定更早的原请求，因此调度器正确停止了不一致的派发。

`tools/retry_scheduler_merge.py` 现在允许显式审核后的版本接续。它要求旧审批条目的完整指纹、旧请求实际成功的 journal attempt、实际返回且已审图拒绝的高清编辑目标、当前失败请求的实际调用前快照，以及完整原词和有序输入字节校验。不能通过修改仍被拒绝的请求来创建新审批版本。旧审批全文进入 `data/retry-approval-versions/`，记录当前归档时间，不倒填为历史调用前审批。

接续审批不调用图片工具，不修改 journal 或重试队列，不重置原图累计次数，也不缩短每次拒绝后的八小时冷却。次数已用尽的来源直接跳过；工具明确禁止重试或请求本身不允许时不能进入审批池。实际调用仍由原有调度、claim 和单路生产执行者负责，在空控制批次的调用间隙执行审批接续与领取。审图、返修和审批不阻塞后续原图生成。

隔离测试覆盖旧审批全文归档、实际字节变化、缺少或过期版本证明、未实际成功的旧请求、进行中的调用和八次上限，均不对本机生产队列作测试写入。文档描述工具能力，某项审批接续、重试和返回是否实际完成以各自回执为准。
