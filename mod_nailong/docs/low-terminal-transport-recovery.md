# LOW 明确网络错误的单次恢复

机器 `bf-202609141645-5434332d4d` 于 2026-10-28 UTC 核对六项 LOW 的历史失败回执：`f538f902`、`17758d47`、`62435d35`、`d9049be6`、`d80f964b`、`fcd80929`。它们实际返回的是连接或网络错误，均有终态 dispatch、原始错误文件 SHA、完整实际调用前快照和有序输入字节证明，没有未知挂起结果或对应成功输出。

逐项完整阅读冻结 prompt 并实际查看全部输入后，将审核配置保存在 `data/production-transport-reviews/20261028-<完整来源SHA>.json`。不可变准备指针交给原有唯一生产执行者；只有它在无活动调用的边界重新核验并准备，随后仍由内置单路工具执行。排队、实际返回图片、人工审图合格分别记录，不把排队写成成功。

`tools/prepare_reviewed_transport_retry.py` 只接受两条明确终态错误文本：`connection failed: error sending request` 与 `network error: error sending request`（均带原有 image generation failed 前缀）。这项恢复每个来源最多一次，保持实际原 prompt、输入顺序/字节和透明参数。含 moderation 的错误、未知结果、已返回图片、服务家族受阻、已有 transport retry 或服务重试链仍拒绝进入此流程。

原先准备器仅支持已有审图拒绝母版的编辑重试。现在也可处理从未返回图片的原图调用，但必须没有生成记录或任何历史母版，输入仅为确切原图和参考图，原图角色、原始 SHA 与 original 路径全部一致。它不使用旧母版占位，也不重新生成已经返回的输出。

同期发现未具名飞行员文件名 `*_ace_m_0`、`*_ace_f_0` 的末尾性别标记会被旧姓氏解析器当作身份，错误关联不同来源。现在这类明确未具名的编号不提供姓氏；相同来源 SHA、实际角色绑定和真正具名人物的变体继续受保护。两个 DLC 同路径素材的服务拒绝保护也保持生效。这是修复错误身份分组，不是改图、改词或解除真实拒绝。

验证：运输恢复及准备边界 23 项测试通过；来源身份、已返回重试美术和服务保护 23 项测试通过。此记录描述技术恢复和已完成人工审核；实际调用、输出和美术结果查对应生成 journal 与生产回执。
