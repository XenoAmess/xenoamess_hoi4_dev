# 奶蛙世界（子项目规则）

继承根目录 `AGENTS.md`。本目录仅服务奶蛙头像模组，不混入其他产品。

- `assets/reference/naiwa.png` 是用户 ZIP 提供的唯一角色身份基准。
- `assets/portraits/<source_sha256>.png` 是逐原图生成并技术缩放后的可重建输入；`data/generated.json` 保存每张来源、提示词、结果与审图。
- `data/catalog.json` 包含原版与本机已安装 DLC 的大/小人物头像库存；生成批次可续跑。原图完全相同才允许去重，不能按相近衣服或同一人物姓名合并不同变体。
- `mod/` 是游戏 payload 源；`mod/gfx/` 由工具生成并忽略；`dist/` 是构建输出，均不手工修改。仅 `tools/build_release.py` 可形成发布 staging。
- 正式构建要求库存无未解析引用、覆盖 100%、每张通过审图；`--preview` 是明确不完整开发包，不得声称正式发布或全人物通过。
- 先完成头像，再考虑 UI 主题。不要为补齐数量而把顾问头像、间谍、通用人物或 DLC 隐藏到分母外。
- 提示词只依据原图可见外观，不将历史姓名/文件名作为外观指令。原图无帽时不能擅加帽子；原图是西装时不能改成军装。用户于 2026-10-16 已决定采用 B 版：全部此前及后续图片保留原人物可见的发型、胡子、眉毛等附属特征，黄色奶龙本体不变。此前光头 A 版作为实验基线保留，不能覆盖后再冒充旧版。正式生产的 `art_direction` 必须为 `hair-features-v1`；旧规则的审图结果不能抵扣迁移。
- 所有生成与返修请求前保存完整实际 prompt，随后保存引用图 SHA、结果 SHA、审图与失败状态。实验资源放在 `experiments/`，与正式头像 manifest 分开。
- 领口专项执行 `collar-fit-v1`：体型适配、闭合/敞开状态、布料前后遮挡与接触阴影、短宽颈部和无奶白领口块均须实际审图。问题图重新生成，当前图片 SHA 对应的专项资格是构建与高优先级完成门禁；见 `docs/collar-fit-production.md`。
- 图片服务拒绝继承根规则：至少冷却 8 小时，允许重试的原请求保持同 prompt、同输入、同工具，最多重试一次；由 `data/image-retry-queue.json` 记录截止、消耗与结果。美术审图返修与服务拒绝分别记录。
