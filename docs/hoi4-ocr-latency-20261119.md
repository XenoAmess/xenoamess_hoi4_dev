# HOI4 截图回传延迟与新鲜输入（本机实证）

适用边界：2026-11-19，机器 `bf-202609141645-5434332d4d`，Windows 主桌面1024×768，Steam中文页脚、HOI4 1.19.5 DirectX11菜单。不是跨机器、任意分辨率或任意客户端主题的固定坐标合同。

跨工具等待可能让已经人工看过的截图超过输入门禁。此次原始截图004虽实际显示离线模式，后续执行时已超过180秒，启动在Popen前停止；该失败保留，未倒填成成功。解决方法是把新截图、实际OCR、目标与尺寸核对、一次输入放在同一执行中；旧截图只作离线校准或已人工识别控件的身份模板，不能作当前Steam模式证明。

Steam小字原色OCR漏字。保留原始截图，取页脚原像素的绿色通道、自动对比度、反色、2倍LANCZOS和20像素白边后，离线校准读出完整“离线模式”。后续实际启动使用重新拍摄的005原图，重新OCR准确读出同样文字，并在30秒内核对焦点、当前尺寸后一次启动。裁剪图是OCR派生物，不是原图替代；分辨率、窗口布局、文字或识别结果不同就停止。完整成功启动和失败门禁见[真实回执](../mod_nailong/data/update-plans/20261119-mainmenu-qa-attempt.json)。

当时可用的Windows OCR语言只有`zh-Hans-CN`。HOI4英文按钮出现漏字和拆字，不能把不准确文本强配成目标。Single Player定位未通过，未发出点击。正式Quit退出使用人工已经看过的原始主菜单按钮作为身份模板：再次取得完整原始截图，核对尺寸、目标HWND与该按钮全部像素相同，再通过`tools/desktop.py click`提供明确1:1内容矩形和X/Y，30秒内点击一次；随后取得新原图和独立进程消失证据。该操作没有调用UIA、隐藏业务接口、内存、注入或终止进程。

每次控件操作仍须先识别真实界面。模板不匹配、OCR缺失或歧义、尺寸变化、黑屏或冻结时停止；不能为赶交接重复点击、放宽为猜测或沿用旧状态。输入回执只证明发出动作，业务结果另看新截图。国家选择和人物显示尚未实测，不能从主菜单启动、原尺寸对照页或构建推断通过。
